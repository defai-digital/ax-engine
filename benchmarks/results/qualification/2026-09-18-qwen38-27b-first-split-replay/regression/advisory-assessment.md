# Forced replay advisory review assessment

Claude reviewed the complete frozen patch without tools and found no proven helper correctness defect. Its integration questions were checked against the final source and the independent code audit. Grok and Qwen complete-patch calls reached the 180-second deadline without findings; their receipts are retained and are not passes. Both shorter helper retries also reached the same deadline without findings. No timeout is counted as an approval. Earlier experiment/prefill reviews by Grok and Qwen did complete and informed the admitted diagnostic design.

- Forced replay already disables projected replay through `linear_mtp_projected_replay_allowed` and requires singleton state replay through `linear_mtp_requires_singleton_replay`. Explicit optimistic acceptance remains excluded; it does still discard skip-state when forced. No assertion or new precedence change is needed for the claimed non-optimistic scope.
- The old acceptance count is used only for the pre-replay decision and sampled residual calculation. The latter returns no correction for greedy requests. The final count is rebound before hidden slicing, correction selection, tuple return, head refolding, output and counters. No stale-count consumer was found in that interval.
- Downstream code uses the corrected count and safe predicted access. Indexed predicted access occurs in the original acceptance helper, before replacement. The shortened canonical prediction vector therefore does not introduce the suggested indexing defect.
- Acceptance remains capped by the batched provisional count. A batched rejection may become a correction token equal to the proposed token; statistics report the conservative committed draft count, not all hypothetical singleton-acceptable drafts. This is an intentional limit, not a claim of maximum acceptance or improved speed.
- This guarantee excludes repetition and no-repeat-ngram processors. It does not extend the runtime's sampling/constraint support. Existing QMM and verifier scopes are thread-local RAII guards; the QMM guard already has its own nesting regression.
- The false batched predictions are injected deliberately. The tiny fixture's argmax is stable and its nonempty K/V depends on consumed input. This reproduces the control-flow defect and tests retained cache contents; it does not reproduce Qwen numerical drift, prove full runner/head-refold integration or make logits sensitive to cache perturbation.
- The SKU live-MTP observer proves a same-state path-sensitive score difference only. It does not identify a unique custom-QMM defect, actual direct-cache identity or whole-request direct equivalence.

No additional production change was justified by these advisory findings. The final installed-wheel controls remain required, with failure artifacts preserved.
